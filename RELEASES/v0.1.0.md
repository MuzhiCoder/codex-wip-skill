# Codex WIP v0.1.0

First public release of **Codex WIP**, a repository-grounded continuity Skill / Plugin for long-running OpenAI Codex coding work.

## Why it exists

A long Codex task can be interrupted by usage-limit exhaustion, provider/account switching, an inaccessible conversation, a crash, context loss, or a machine change. The code may still exist while the engineering context does not.

Codex WIP makes continuity durable by treating **Git + verifiable WIP artifacts** as the recovery boundary rather than depending on one cloud conversation remaining available.

## Core commands

- `$wip checkpoint` — persist a lightweight, verifiable checkpoint.
- `$wip handoff` — prepare a provider/account/session/machine handoff.
- `$wip recover` — reconstruct interrupted work from Git, tests, code relationships, and saved evidence.
- `$wip resume` — verify checkpoint freshness and continue from the first verified next action.
- `$wip status` — inspect checkpoint freshness and repository drift without changing business code.

## Install from the public Codex marketplace

```bash
codex plugin marketplace add MuzhiCoder/codex-wip-skill --ref main
codex plugin add codex-wip@codex-wip-skill
```

Start a new Codex thread after installation and run:

```text
$wip status
```

## Safety defaults

Codex WIP does not persist raw diffs, business file contents, environment-variable values, API keys, access tokens, cookies, passwords, or authorization headers by default.

Recovery does not automatically execute `git reset --hard`, `git clean`, force push, history rewriting, commit, or push.
